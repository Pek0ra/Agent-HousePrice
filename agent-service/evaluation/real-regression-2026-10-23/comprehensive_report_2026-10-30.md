## 1. 一页结论

本次启动的真实服务完成了审核版 20 题：20/20 请求返回 HTTP 200，20/20 选中了预期数据源，10/10 需要 SQL 的题目实际执行了 SQL。逐题按“回答内容、数值、政策证据和安全边界”复核，**11 题通过、4 题部分通过、5 题未通过**。HTTP 200 只说明请求正常返回，不能代表回答正确。

同时，当前代码的 Python 全量测试为 **140 passed、2 warnings**；路由、MySQL Agent 与 API 定向测试为 **81 passed、1 warning**。健康冒烟检查：Python Agent、Java 后端、前端均 HTTP 200，HiveServer2 为 healthy。警告来自 Starlette 的废弃接口提示和本地 Qdrant 的 payload index 限制；本次未观察到测试断言失败。

最重要的未通过问题是：官方仍有效的 360/565 号文件被内部 RAG 审核标记挡住（BLD07/08），地区实体“朝阳区/海淀区”被错误截成“朝阳/海淀”（BLD13），零条无效面积记录被当成无数据（BLD15），以及限购政策漏掉 2025 年中间版本（BLD10）。这些问题应作为真实缺陷保留，不能通过修改金标准消除。

## 2. 测试环境与判断方法

运行中的 Docker 服务包括 Python Agent、Java 后端、MySQL、Hive、Qdrant、Hadoop 和前端。20 题通过真实 /api/v1/chat 请求执行，保存了每题请求、回答、SQL、返回行、路由建议、政策证据、trace 与耗时。项目房价数据为**合成 CSV**；此测试验证 Agent 对该数据和已收录政策的处理，不验证真实房价预测能力，也不能用样本均值代表市场均价。

本次判定分三档：
- **通过**：核心事实、数据源或政策依据符合审核版标准；可有不影响结论的表述瑕疵。
- **部分通过**：安全方向或部分证据正确，但关键时间说明、回答直达性、检索相关性或数值存在缺口。
- **未通过**：核心结论错误、缺失必要政策依据，或 SQL 产生错误结果。

金标准是在本轮运行前确定的。历史 80 题和旧版 20 题的原始结果没有覆盖；旧版 20 题的“未评分”记录也不冒充本轮成绩。原始 CSV 因 Excel 占用保留，审核版另存为 human_annotation_reviewed.csv；后续 run_new20.py 已从审核版读取题目。当前结果中的“通过/部分通过/未通过”是逐题人工判读，尚未实现自动 CI 阻断。
